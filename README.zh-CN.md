# sync-watch-room

[English](./README.md) | **简体中文**

一个基于 Vue 3、Node.js、WebSocket 和 WebRTC 的轻量级同步观影项目。创建房间、载入 OSS/CDN 视频，即可同步播放、文字聊天和实时语音。

> 项目目标是尽量降低用户感知到的播放偏差，不承诺不同网络和设备之间实现零延迟播放。

## 功能

- 基于服务端校准时钟，定时执行播放、暂停和拖动指令
- 小幅偏差平滑追帧，大幅偏差直接跳转到权威进度
- 感知成员缓存状态，等待全员可播放后统一开始
- 展示每位成员的缓存进度、延迟、丢包、语音和连接状态
- 实时聊天、正在输入状态、房间事件和成员在线状态
- WebRTC 多人语音、静音、RNNoise 降噪和麦克风音量调节
- 后端签发短期 TURN 凭证，WebRTC 直连失败时自动回退中继
- WebSocket 心跳检测、房间状态恢复和房主自动转移
- 浏览器原生播放 MP4/WebM，通过 `hls.js` 播放 HLS/M3U8
- 支持桌面端与移动端，并提供移动端全屏播放控制

## 技术架构

```text
                         播放状态 / 聊天 / 信令
┌──────────────┐        WebSocket        ┌──────────────────┐
│    浏览器 A   │ ◀────────────────────▶ │   Node.js 服务   │
└──────┬───────┘                         └──────────────────┘
       │  WebRTC DataChannel + 语音              ▲
       ▼                                          │
┌──────────────┐                                  │
│    浏览器 B   │ ─────────────────────────────────┘
└──────┬───────┘
       │ HTTPS 媒体请求
       ▼
┌──────────────┐
│   OSS / CDN  │
└──────────────┘
```

- **WebSocket**：保存可恢复的房间状态，并负责聊天、心跳、房主选举和 WebRTC 信令。
- **WebRTC DataChannel**：传递输入状态和 P2P 延迟测量；播放控制统一使用服务端权威 WebSocket 通道。
- **WebRTC 音轨**：提供点对点语音通话。
- **OSS/CDN**：存储和分发视频，视频字节不经过房间服务器。

## 环境要求

- Node.js 20.19 或更高版本
- 支持 WebSocket、WebRTC、Web Audio 和 MediaSource 的现代浏览器
- 生产环境使用 HTTPS，以支持麦克风权限和安全 WebSocket

## 快速开始

```bash
git clone https://github.com/<your-account>/sync-watch-room.git
cd sync-watch-room
npm install
npm run setup:env -- --domain localhost --turn-domain localhost
# .env 中需设置 DATABASE_URL；使用项目本地 PostgreSQL：
docker compose up -d --wait postgres
npm run dev
```

打开 [http://localhost:4173](http://localhost:4173)。

开发模式下：

- Vite 前端运行在 `4173` 端口。
- Node.js WebSocket 服务运行在 `4174` 端口。
- Vite 将 `/ws` 和 `/api` 代理到后端。
- 开发后端允许 `localhost:4173` 和 `127.0.0.1:4173`，覆盖 `.env` 中的生产域名限制。

## 视频片源

首页公开管理员启用的资源，支持封面、卡片/列表视图、按影片归并和选集。浏览无需登录；登录后可开房、同步观看，并在“继续观看”恢复个人进度。管理员通过“管理后台”的 `ADMIN_TOKEN` 维护资源、来源和 OSS 文件。

首页搜索栏上方展示最多 5 条资源推荐，优先使用资源库，资源库为空时使用公开来源的最新资源。推荐每 6 秒轮播，支持暂停、上一条/下一条和直接选集；鼠标悬停、键盘焦点进入或页面隐藏时暂停自动切换，移动端同步适配。轮播、资源卡片和列表行使用固定高度，长标题、简介及状态文字以省略号截断，鼠标悬停显示完整文本提示。

Node.js 后端启动时会读取项目根目录的 `.env`，已由进程环境提供的值优先生效。`DATABASE_URL` 是 PostgreSQL 连接地址。首次启动会读取 `DATA_DIR`（默认项目 `data/`）中的旧 JSON 作为迁移种子；已有数据库记录时以 PostgreSQL 为准，后续数据都写入数据库。

OSS 直传需在 `.env` 中填写 `OSS_REGION`、`OSS_BUCKET`、`OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET` 和公开访问的 `OSS_PUBLIC_URL`。浏览器使用服务端签发的短期 PUT 地址上传 MP4/WebM，密钥不会发送到浏览器。OSS Bucket 必须允许站点来源的 PUT CORS，公开视频需要可通过 `OSS_PUBLIC_URL` 读取。支持单文件 1 GiB 以内；较大文件请先用独立上传工具传至 OSS，再在后台添加其播放地址。

在“管理后台 → 资源库”添加或编辑资源时，点击视频地址旁的“从 OSS 选择”，按文件前缀筛选（留空查看全部），支持分页浏览 MP4、WebM 和 M3U8。选中文件会自动填入公开播放地址，名称为空时使用文件名；点击“保存资源”后发布。

点播 HLS 前会在当前浏览器检查清单、首个分片及关联的初始化文件/密钥（包含跨域访问检查），选集时先检查每条线路的首集。确认 404/410 或清单无效的地址在本次页面会话中隐藏 10 分钟；检查超时、403、跨域或网络异常交由播放器实际尝试，不直接判定资源失效。失败界面的“重试加载”会立即清除本地失败记录并重新加载（所有成员均可操作）；同一分集有其他有效线路时仍可观看，资源库会尝试备用线路。播放器实际确认失败后会暂时屏蔽该地址，可立即重试。跨域请求失败会提示“该资源跨域加载失败”，明确的 CORS 错误提示“该资源被跨域限制”；403/404、超时和断网分别提示。播放中的 HLS 致命网络错误停止加载，解码错误最多恢复一次，可通过“切换线路”继续；清单检查通过不代表整部影片或所有编码都能播放。

也可点击“上传文件”，直接将本机 MP4/WebM 视频上传到 OSS，查看上传进度或取消上传。上传完成并确认文件后，地址自动填入当前资源表单，已有名称、封面和简介会保留；点击“保存资源”后发布或更新。关闭表单不会删除已经上传的 OSS 文件，可稍后通过“从 OSS 选择”使用。

苹果 CMS V10 来源可以在后台添加、编辑、公开、停用或删除，来源设置保存在 PostgreSQL。客户端统一检索启用并公开的来源，以豆瓣标识或片名/年份归并同一影片，只显示线路编号。管理员可快捷添加非凡、量子来源，逐集或整部入库，分集自动归并到资源库。播放器网页地址会被过滤。

`MACCMS_SOURCES=名称|https://example.com/api.php/provide/vod/` 可提供初始来源，多个来源用逗号分隔；已有数据库设置时，以后台保存的来源为准。XML 接口地址末尾的 `/at/xml/` 会自动换成 JSON。一个公开提供采集接口的例子是 [非凡资源](https://ffzy.tv/help/)，M3U8 接口为 `https://api.ffzyapi.com/api.php/provide/vod/from/ffm3u8/`。播放地址仍需允许浏览器跨域访问。

房主可以载入：

- MP4、WebM 或其他浏览器支持的直链媒体地址
- `hls.js` 或 Safari 原生支持的 HLS/M3U8 地址
- 通过短期签名 URL 暴露的私有 OSS/CDN 资源

为了保证拖动和启动稳定：

- 媒体源需开启 HTTPS 和 CORS。
- 返回正确的 `Content-Type` 和 `Content-Length`。
- MP4/WebM 资源需支持 HTTP Range 请求。
- 所有房间成员必须加载完全一致的媒体版本。

项目不直接播放磁力链接或普通 BitTorrent 节点。生产环境如需支持，应由独立下载/转码任务导入已授权内容，再发布到 OSS/CDN。


## 用户、剧集与 PostgreSQL

- 用户密码使用随机盐和 scrypt 保存，登录会话使用 HttpOnly Cookie；用户只能读取自己的历史与进度。
- 剧集支持从任意分集进入、房主切集、自动续播和保留进度切换线路。
- “继续观看”会恢复未看完的进度；看完一集可继续下一集，最后一集看完后可重新观看。
- 观看历史支持逐条删除和清理失效记录。资源已下架、剧集已移除或网络来源已停用时会标记不可用；仍有启用的公开网络来源的记录会保留，即使没有入库。
- 独立观看合集功能已移除。剧集在资源库自动归并并支持选集，后台“整部入库”可一次采集全部分集。
- PostgreSQL 本地服务仅绑定 `127.0.0.1`，默认端口 `55432`。使用 `npm run setup:env` 生成数据库密码和连接配置，然后执行 `docker compose up -d --wait postgres`。
- `SESSION_COOKIE_SECURE` 在生产环境默认为 `true`；开发命令固定使用本地 HTTP Cookie 配置。生产入口需要 HTTPS。
- `npm test` 的集成测试使用 `.env` 中的数据库地址，并创建、清理独立测试 schema，不改动正常数据。

## 播放同步

房主操作会携带 `executeAt` 时间戳并提前发送。客户端按照校准后的服务端时钟执行，而不是在收到消息时立即执行。

- 服务端每 50ms 下发权威播放状态，持续校准不依赖 P2P 连接。
- 小偏差通过短暂变速追齐；偏差超过 150ms 时全房间暂停对齐。起播要求所有成员确认同一指令序号，并对齐到 80ms 以内。
- 成员缓冲、进度报告过期或信令延迟超过 150ms 时暂停等待。客户端超过 300ms 收不到有效同步信号就停止播放。
- 全员至少有 1.5 秒可播放缓存后才共同起播。断网恢复或页面回到前台后重新同步；[后台页面的浏览器定时器可能受到节流](https://developer.chrome.com/blog/timer-throttling-in-chrome-88/)，因此切到后台也会暂停同步播放。
- 成员连接断开时房间保持暂停，由房主确认后继续，其他成员不会自动独播。

目标是播放偏差小于 1 秒，网络不佳时优先暂停等待。完全断网或被系统挂起的设备无法接收新画面及拖动指令，此时不承诺继续播放。

本次同步机制更新后，房间内所有浏览器需刷新后重新加入；服务端会拒绝使用旧同步协议的客户端。

播放器下方支持选择 HLS 片源实际提供的画质档位，并可切回“自动”。每位成员独立选择画质，影片和共同进度保持一致；切换后若缓存不足，继续按全房间同步规则暂停等待。单档位或直接 MP4/WebM 显示原画；只能原生播放 HLS 的浏览器使用自动画质。

## 语音处理

语音通过 WebRTC 音轨传输。麦克风设置包括：

- 基于 RNNoise 的实时降噪
- 可完全关闭的麦克风降噪开关
- `0%`（静音）到 `250%`（放大）的麦克风音量
- 麦克风静音和成员语音状态

P2P 直连时语音不会经过房间服务器。直连失败时，后端会为内置 coturn 服务签发短期凭证，WebRTC 自动尝试 TURN 中继；成员网络状态会显示当前使用 `P2P` 还是 `TURN`。TURN 会消耗服务器带宽，需要按并发量规划容量。

## 生产部署

仓库内已经提供 Vue 前端、Node.js 信令后端和 coturn 中继服务，以及 Nginx WebSocket 反向代理、健康检查、优雅退出和 Docker Compose 编排。

```bash
npm run setup:env
# 对外开放前，请检查生成的域名、公网 IP 和 TURN 配置。
docker compose up --build -d
```

访问 `http://localhost:8088`。生产环境需要在该入口前配置 HTTPS 负载均衡或反向代理。环境变量、独立部署、健康检查、升级流程和扩容限制见[部署指南](./docs/deployment.zh-CN.md)。

服务端仍将房间与聊天记录保存在进程内存中。在房间状态迁移到共享存储、WebSocket 支持按房间路由之前，后端应保持单实例运行。

## 项目状态

这是一个可运行的单实例版本：资源、来源、用户、登录会话、个人观看历史和房间检查点保存在 PostgreSQL。运行中的房间成员和 WebRTC 连接由当前进程维护；网络中断可重连，最近 24 小时的房间可从检查点恢复。
